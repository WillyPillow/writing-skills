# PEP 383: Non-decodable Bytes in System Character Interfaces

## Summary

File names, environment variables and command-line arguments are defined as character data in POSIX. The C interfaces that carry them, however, accept arbitrary bytes, and those bytes need not conform to any encoding. This PEP proposes a way to handle such bytes in Python. The bytes are embedded in character strings in a form that allows the original byte string to be recreated exactly.

## Problem

POSIX defines file names, environment variables and command-line arguments as character data. A program that reads one of them and expects text can be given a byte sequence that is not valid in the expected encoding. The C interfaces do not reject these sequences, so they reach the program. A program written in Python has to decide what to do with them.

The material locates the problem in the gap between the definition and the interface. The definition says the values are characters. The interface passes bytes. Where the two disagree, a byte sequence can arrive that has no character interpretation in the expected encoding.

## Proposal

The proposal embeds the bytes in character strings. The embedding must let the original byte string be recreated from the character string, so that no byte is lost on the way through a string interface.

## What the proposal does not claim

The summary does not say that the embedding makes a program correct for all byte sequences. It says only that the original bytes can be recreated. A program that treats an embedded byte as a character may still misbehave. This document does not claim more than the summary does.
