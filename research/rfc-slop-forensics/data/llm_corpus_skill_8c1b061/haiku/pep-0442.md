## Abstract

This PEP proposes to remove the current limitations on object finalization. Its goal is to define and run finalizers for any object, whatever its position in the object graph. The PEP does not change any Python code. Objects with existing finalizers benefit without modification.

## Motivation

A finalizer runs when an object is about to be destroyed, so that the object can release resources such as files, sockets, or locks. The current rules restrict which objects can have a finalizer that runs safely. The restriction depends on the object's place in the object graph. ## Decisions

The first decision is to change the mechanism inside the interpreter rather than add a new user-facing API. The force is the goal of running finalizers for any object. A new API would leave existing finalizers in place with their current limits, and would require every author to adopt it. [TODO: confirm whether a new API was considered and why it lost.]
