Title: Inclusion of implicit pip bootstrap in Python installation
Status: Draft. [TODO: confirm status and the target Python version]

## Abstract

This PEP proposes that a pip bootstrap executable be included in the Python installation. The aim is to make third-party modules easier to use for Python users. The PEP does not propose to include the pip implementation in the standard library, and it does not propose any package management mechanism beyond the ones that PEP 427 and the distlib PEP provide.

## Motivation

A Python user who wants a third-party module must first find a way to install it. Installation tools are not part of every Python installation, so a new user may have no way to start. ## Goals and non-goals

Goal: a user who has a Python installation can install a third-party module without first finding and installing a package manager. We would know this goal was met if a fresh installation can install a module with the bootstrap and no other download. [TODO: confirm this test.]

Non-goal: putting pip in the standard library. The standard library and the package manager remain separate.

Non-goal: a new package format or installation mechanism. The PEP uses PEP 427 as it stands.

## Decisions

The first decision is to ship a bootstrap, not the package manager itself. The force is the goal of a default path to third-party modules, without a change to the standard library. Including pip directly would tie the standard library to one package manager's release cycle. [TODO: confirm this reason and whether it is the deciding one. State whether any other factor weighs in the same direction.]

The second decision is to rely on the wheel format that PEP 427 defines. The reason is that the format already exists, so no new one has to be designed and supported. [TODO: confirm this reason.]

The cost of the first decision is that the bootstrap depends on something that is not part of the installation, unless the bootstrap bundles pip. [TODO: state which of these the design does, and the size or maintenance cost of the choice if the author has an estimate.]

Reversibility: an installed executable can be removed in a later release, but users who depend on it will notice. The name of the executable is the part with the highest cost to change.
