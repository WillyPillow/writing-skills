# PEP 223: Change the Meaning of `\x` Escapes

## Abstract

This PEP changes `\x` escapes, in both 8-bit and Unicode strings, so that each one consumes exactly the two hexadecimal digits that follow it. The proposal treats this as the correction of an original design flaw. It argues that the change gives clearer expression in every kind of string literal, a cleaner Unicode story, better compatibility with Perl regular expressions, and minimal risk to existing code. ## Specification

Under the proposal, `\x` followed by any text consumes exactly two hexadecimal digits. Any further hexadecimal digits are ordinary characters. For example, under the proposed rule, `"\x41BC"` yields the character `A` followed by the two characters `B` and `C`. ## Rationale

A fixed width gives each escape a clear end point. A reader can scan a string and find the boundaries of each escape without reading ahead.
