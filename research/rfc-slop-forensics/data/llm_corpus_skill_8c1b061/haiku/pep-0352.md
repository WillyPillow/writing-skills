## Abstract

In Python 2.4 and earlier, any classic class can be raised as an exception. The plan for Python 2.5 was to allow new-style classes as exceptions, but that change makes the problem worse. It would mean that any class, or any instance of any class, can be raised. Because of this, no guarantee can be made about the interface of exceptions.

This PEP proposes a new superclass that every raised object must inherit from. The restriction gives exceptions a standard interface that code can rely on. It also gives all exceptions one known hierarchy to follow.

## Motivation

The problem is that the language does not constrain what can be raised. A handler written for one exception has to guess what attributes and methods the raised object provides, because the object may come from any class. The guarantee that an exception has a known interface is missing. [TODO: give a concrete failure from the material, such as a handler that breaks on an object raised from an unrelated class.]
