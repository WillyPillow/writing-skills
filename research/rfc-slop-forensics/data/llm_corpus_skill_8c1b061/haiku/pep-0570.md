## Abstract

This PEP proposes a new syntax, a slash (`/`), for marking positional-only parameters in function definitions. A positional-only parameter has no name that a caller can use. When a function with such parameters is called, positional arguments are matched to them by their order alone.

## Motivation

Library authors design APIs so that callers use them correctly and as intended. Part of that design is the choice of parameter names. Without a way to mark parameters as positional-only, the author must choose names carefully, because each name becomes part of the interface that callers can use. ## Proposal

A function definition may include a `/` in its parameter list. Every parameter that appears before the slash is positional-only. [TODO: give the exact rule for a parameter that appears after the slash, and for a function with no slash.]

## Goals and non-goals

Goal: a library author can state that certain parameters have no externally usable name, so that their names may change without breaking callers. ## Decisions

The first decision is to mark positional-only parameters with a syntax in the definition itself. The force is that the restriction belongs to the function's interface, so it should be written where the interface is written.
