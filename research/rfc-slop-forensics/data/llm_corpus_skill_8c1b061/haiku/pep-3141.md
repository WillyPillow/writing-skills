# PEP 3141: A Type Hierarchy for Numbers

## Abstract

This proposal defines a hierarchy of abstract base classes (ABCs), building on PEP 3119, to represent number-like classes. The hierarchy has five levels: `Number`, `Complex`, `Real`, `Rational` and `Integral`. In the notation used here, `A :> B` means that A is a supertype of B, so the hierarchy reads `Number :> Complex :> Real :> Rational :> Integral`. The design is inspired by the numeric tower of the Scheme language. [TODO: give the full citation for the Scheme numeric tower.]

## Motivation

Python code often needs to ask whether a value is a number of some kind. A function that computes a mean may accept any real value. A function that solves a polynomial may accept any complex value. Today the only way to ask is to test for concrete types, such as `int` or `float`, or to rely on duck typing and catch the errors that follow when a value does not behave as expected. ## Specification

Each level of the hierarchy is an abstract base class. A class that implements the operations of a level is registered as belonging to it. The levels are nested. Every `Integral` value is a `Rational`, every `Rational` is a `Real`, every `Real` is a `Complex`, and every `Complex` is a `Number`. Each level of the hierarchy names a set of operations. Code that asks for a `Real` may use ordering and arithmetic on it. Code that asks for an `Integral` may also use operations that need exact integer values. [TODO: list the operations assigned to each level.]

## Rationale

The chain is linear. Each level adds one capability to the level above it. A linear chain is easy to explain, and it matches the way mathematicians describe these sets: the integers are a subset of the rationals, the rationals of the reals, and the reals of the complex numbers.
