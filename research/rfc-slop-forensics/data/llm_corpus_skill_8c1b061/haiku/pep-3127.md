## Abstract

This PEP proposes changes to the Python core that rationalize how integers are written as string literals in different radices, that is, bases. The changes target Python 3.0. The backward-compatible parts of the changes should also be added to Python 2.6, so that every valid Python 3.0 integer literal is also valid in Python 2.6.

The proposal has three parts. First, an octal literal must be written with a leading `0o` or `0O`, instead of a leading `0`. Second, binary literals are supported with a leading `0b` or `0B`. Third, binary numbers are supported in string formatting.

Integer literals in Python 2 do not share one form across bases. The most visible example is the octal literal, which is written with a leading zero. ## Proposal

The octal form changes. A literal written with a leading `0` is no longer an octal literal, and octal literals require `0o` or `0O`. The binary form is new, and it uses `0b` or `0B`. ## Compatibility

The change to octal literals is the part most likely to break existing code. Any program that writes an octal literal with a leading zero must be updated to use the new prefix when it moves to Python 3.0.
