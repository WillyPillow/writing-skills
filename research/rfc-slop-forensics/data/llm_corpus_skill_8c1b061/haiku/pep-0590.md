# PEP 590: Vectorcall: a fast calling protocol for CPython

## Abstract

This PEP introduces a new C API to optimize calls to objects. It defines a new "vectorcall" protocol and calling convention. The convention is based on the "fastcall" convention that CPython already uses internally. Any user-defined extension class can use the new features. Most of the new API is private in CPython 3.8. The plan is to finalize the semantics and make the API public in Python 3.9.

This PEP deals only with the Python/C API. It does not change the Python language or the standard library. [TODO: confirm the release plan against the author's current status, since the plan's dates belong to the time of writing.]

## Motivation

Calling an object from C involves packing its arguments into a container, typically a tuple, and then unpacking that container on the other side. ## Rationale

The protocol follows fastcall because fastcall is already used and tested inside CPython. Reusing a convention that the interpreter already runs is the strongest argument for it, because the new code paths share a model with code that is already in production.
