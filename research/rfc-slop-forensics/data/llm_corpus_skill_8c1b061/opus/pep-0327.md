# PEP 327: Decimal data type

## Abstract

This PEP proposes a `Decimal` data type for every use where decimal numbers are needed and binary floating point is too inexact. `Decimal` supports the Python standard functions and operations, and complies with the decimal arithmetic standard ANSI X3.274-1996 [1]. It is a floating-point type, not a fixed-point one, with bounded precision: the precision is the maximum number of significant digits in a result. The precision can be set by the user, and trailing zeros are kept as significant, so the type can also be used for fixed-point work.

The work is based on code and tests written by Eric Price, Aahz and Tim Peters. Just before Python 2.4a1, the `decimal.py` reference implementation was moved into the standard library. [TODO: the rest of the abstract after this point.]

## Motivation

Python's `float` is a binary floating-point number. Most decimal fractions have no exact binary representation, so a value such as 0.1 is stored as the nearest binary fraction. The difference is small, but it becomes visible in ordinary arithmetic:

```python
>>> 0.1 + 0.2 == 0.3
False
```

For scientific computation, this is acceptable: the inputs are themselves approximate, and the error is bounded and well understood. For other uses, it is not. Monetary amounts are the main case. An amount such as 19.99 is exact by definition, and a program that adds a column of prices must produce the exact total that a person would get by hand. Accounting rules and legal requirements may also specify how and when values are rounded. Programs can work around `float` today by storing amounts as integers in the smallest unit, such as cents. This works when every value has the same number of decimal places, but it pushes the bookkeeping of where the decimal point is onto the programmer, and it does not handle values with mixed scales, such as an interest rate multiplied by an amount. ## Requirements

1. Decimal values are exact. A value written as `"19.99"` is stored as nineteen and ninety-nine hundredths.
2. Arithmetic follows ANSI X3.274-1996, so that results can be checked against the standard and against other implementations of it.
3. The type works with the standard operators and built-in functions, so that a program can use it where it now uses `float`, with few other changes.
4. The user controls precision and rounding.

## Specification

### Floating point with bounded precision

A `Decimal` value is represented by a sign, a coefficient that is an integer of any number of decimal digits, and an exponent. The value is the coefficient times ten to the power of the exponent. [TODO: confirm this representation against the reference implementation.]

The type is floating point. The exponent of a result is chosen by the operation, not fixed in advance by the type. The precision bounds how many digits the coefficient of a result may have. When an exact result needs more digits, it is rounded to the precision.

The precision limits results, not inputs. A `Decimal` constructed from a string with more digits than the current precision keeps all of them. [TODO: confirm. If construction rounds to the context precision instead, change this paragraph.]

Fixed-point use is still possible because trailing zeros are significant. The values `Decimal("1.0")` and `Decimal("1.00")` compare equal, but they are distinct representations: the first has one digit after the point and the second has two. Arithmetic preserves this information. Adding `Decimal("1.30")` and `Decimal("1.20")` gives `Decimal("2.50")`, not `Decimal("2.5")`. A program that keeps all its amounts at two decimal places therefore gets results at two decimal places, without any extra code, as long as the results stay within the precision. ### Construction

A `Decimal` can be constructed from a string or from an integer. Both conversions are exact.

Construction from a `float` needs a decision. A `float` holds an exact binary fraction, which has an exact decimal representation, but that representation is usually not the value the programmer wrote. `float(0.1)` is not one tenth. An exact conversion would produce a long string of digits that surprises most users. A conversion rounded to the shortest decimal that reads back to the same float would match what the programmer wrote, but would hide the fact that the `float` was already inexact.
