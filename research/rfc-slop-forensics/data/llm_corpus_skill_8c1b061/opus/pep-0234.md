# PEP 234: Iterators

## Abstract

This document proposes an interface through which an object controls how a `for` loop iterates over it. The object provides a method that returns an iterator. The iterator provides one operation, "get next value", which returns the next item each time it is called and raises an exception when no more items are available. The document also proposes iterators over the keys of a dictionary and over the lines of a file, and proposes that `dict.has_key(key)` may be spelled `key in dict`.

## Background

In Python 2.1 and earlier, a `for` loop over an object calls `__getitem__` with the indexes 0, 1, 2 and so on, until the call raises `IndexError`. [TODO: confirm this description of the current protocol.] This works for sequences, but it forces any object that wants to support `for` to pretend to be a sequence. An object that produces values one at a time, such as a file or a generator of values computed on demand, must accept an index argument that it does not need, and must usually check that the index equals the previous one plus one.

The sequence protocol also makes iteration over a dictionary awkward. A dictionary does not have positions, so `for` cannot be applied to it directly. A program must call `keys()`, `values()` or `items()`, each of which builds a complete list before the loop starts. For a large dictionary, the list costs memory proportional to the dictionary's size, only to be thrown away after the loop. ## Specification

### The iteration protocol

An object is iterable if it provides a method that returns an iterator. This document calls that method `__iter__()`. An iterator is an object that provides a method, called `next()` here, which returns the next item or raises `StopIteration` when there are no more items. [TODO: confirm the method and exception names against the checked-in implementation.]

An iterator is itself iterable: its `__iter__()` returns the iterator itself. This lets a `for` loop accept either an iterable or an iterator, and lets a program advance an iterator by hand for a few items and then hand the rest to a `for` loop.

A `for` loop over `obj` is executed as follows:

1. Obtain an iterator by calling `obj`'s `__iter__()` method.
2. Call the iterator's `next()` method.
3. If the call raises `StopIteration`, end the loop.
4. Otherwise, bind the returned value to the loop target, execute the loop body, and go back to step 2.

### The `iter()` built-in

A new built-in function `iter(obj)` returns an iterator for `obj`. If `obj` provides `__iter__()`, `iter()` calls it. If `obj` does not provide `__iter__()` but supports the sequence protocol, `iter()` returns an iterator that calls `__getitem__` with increasing indexes and stops at `IndexError`, so that existing sequences remain iterable. ### Iteration over dictionaries

A dictionary is iterable. Iterating over it yields its keys. The loop

```python
for key in d:
    print key, d[key]
```

visits each key once, without building a list of keys first.

### Iteration over files

A file object is iterable, and iterating over it yields its lines, as `readline()` would. The loop

```python
for line in f:
    process(line)
```

reads one line at a time and stops at end of file.

### `key in dict`

The `in` operator, applied to a dictionary, tests whether the key is present:

```python
if key in d:
    ...
```

This is equivalent to `d.has_key(key)`. The spelling is shorter and matches the meaning of `for key in d`. [TODO: whether `has_key` is to be deprecated.]

## Design decisions

### A separate iterator object

The protocol separates the iterable from the iterator. An object such as a list or a dictionary can then support any number of independent iterations at once, each with its own position, because each `for` loop calls `__iter__()` and gets a fresh iterator. If the iteration state lived on the object itself, two nested loops over the same list would interfere.

### Ending iteration with an exception

The end of iteration is signalled by an exception rather than by a special return value. Any value, including `None`, can be a legitimate item, so no return value can safely mean "no more items".
