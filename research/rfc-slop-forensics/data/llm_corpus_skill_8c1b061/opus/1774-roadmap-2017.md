# Summary

This RFC proposes the 2017 Rust roadmap, following the process set out in RFC 1728. The roadmap says where the Rust project should be by the end of 2017. This year's focus is to make Rust users more productive, while keeping the language's emphasis on fast, reliable code.

By the end of 2017:

- Rust should have a lower learning curve.
- Rust should have a pleasant edit-compile-debug cycle.
- Rust should provide a solid, but basic, IDE experience.
- Rust should provide easy access to high-quality crates.
- Rust should be well equipped for writing robust servers that handle high load.
- Rust should have 1.0-level crates for essential tasks.
- Rust should integrate easily into large build systems.
- Rust's community should provide mentoring at all levels.

# Motivation

RFC 1728 asks the project to publish a roadmap each year so that contributors across teams work toward shared goals, and so that users can see what to expect. This RFC is that roadmap for 2017.

The choice of productivity as the theme needs evidence that productivity is where Rust falls short today. [TODO: the evidence the roadmap rests on. The qualifier matters as much as the theme. Rust's emphasis is on fast, reliable code, and a change that made Rust easier to learn by weakening that emphasis would trade away what the language is for. Each goal below is therefore to be met without giving up run-time performance or the safety guarantees of the type system.

# Drawbacks

A roadmap focused on productivity draws effort away from other work. Features that do not serve any of the goals above, such as new language features with narrower uses, will receive less attention from the teams during 2017. Contributors who want to work on them can still do so, but review and design time from the core teams is limited.

The goals are broad, and several are not yet stated in a form that can be checked at the end of the year. A roadmap whose goals cannot be checked cannot be evaluated by the retrospective RFC 1728 asks for. Publishing a goal creates an expectation. If the IDE experience or compile times do not improve noticeably during the year, users who read the roadmap will be disappointed, and the next roadmap will be taken less seriously.
