# PEP 590: Vectorcall: a fast calling protocol for CPython

## Abstract

This PEP introduces a new C API for optimizing calls of objects. It defines a "vectorcall" protocol and calling convention. The convention builds on the "fastcall" convention, which CPython already uses internally. Any user-defined extension class can use the new features.

Most of the new API is private in CPython 3.8. The plan is to finalize the semantics and make the API public in Python 3.9.

**Note:** This PEP deals only with the Python/C API. It does not affect the Python language or the standard library.

## Motivation

A call in CPython passes its arguments to the callee in some packed form. Under the older `tp_call` convention, the caller builds a tuple of positional arguments and, if there are keyword arguments, a dict. The callee then unpacks them. For a call of a small function with a few arguments, building and discarding the tuple and dict is work that does not contribute to the result.

The "fastcall" convention avoids that work inside the interpreter. Arguments are passed as a C array and a count, with keyword names in a separate tuple. ## Specification

### Vectorcall

A callable that supports vectorcall provides a function with a signature that takes:

1. the callable itself,
2. a pointer to an array of positional-then-keyword argument values,
3. the number of positional arguments, and
4. a tuple of keyword argument names, or null when there are none.

## Scope

The PEP covers the Python/C API only. The Python language and the standard library are unchanged. A Python programmer who calls a function sees the same behavior before and after. Only C code that defines or invokes callables can observe the new API.
