# PEP 570: Python Positional-Only Parameters

## Abstract

This PEP proposes a new syntax, `/`, for specifying positional-only parameters in Python function definitions. Positional-only parameters have no externally usable name. When a function accepting positional-only parameters is called, positional arguments are mapped to these parameters based solely on their order.

When designing application programming interfaces (APIs), library authors try to ensure correct and intended usage of an API. Without the ability to specify which parameters are positional-only, library authors must be careful when choosing appropriate parameter names. This care must be taken even for required parameters or when the parameters have no external semantic meaning for callers of the API.

## Motivation

In Python today, every parameter that a `def` statement declares can be passed by name. A function `f(a, b)` accepts `f(1, 2)`, `f(a=1, b=2)` and `f(1, b=2)`. The name of each parameter is therefore part of the function's public interface, whether or not the author wanted it to be.

For a library author, that has a cost. Once users call `f(a=1)`, renaming `a` breaks them. The author must choose names that will last, even for parameters whose names carry no meaning to the caller. A function that takes one required value and operates on it gains nothing from a name, and the name now has to be kept forever.

Some functions in Python already have parameters that cannot be passed by name. These are implemented in C, and their signatures have no names to bind to. A Python function that wants the same behavior has no way to say so, which makes it impossible to write a Python function with the exact signature of a built-in one. The result is a gap between what C functions can do and what Python functions can do. The gap shows up when a Python class tries to mimic a built-in, or when a library author wants to reserve the right to rename a parameter later.

## Rationale

The proposal is to mark the end of the positional-only parameters with a `/` in the parameter list. Every parameter to the left of the marker is positional-only. Every parameter to the right can be passed either way, or by name only if it also follows a `*`.

```python
def f(a, b, /, c, d, *, e, f):
    ...
```

In this example, `a` and `b` are positional-only, `c` and `d` can be passed either way, and `e` and `f` are keyword-only. The marker mirrors the existing `*` marker, which already separates parameters that can be passed positionally from those that must be named. ## Backward compatibility

Existing function definitions contain no `/`, so none of them changes meaning. A `/` in a parameter list is a syntax error in the current language.
