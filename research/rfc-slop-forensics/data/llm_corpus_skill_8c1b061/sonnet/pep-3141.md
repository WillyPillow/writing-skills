# PEP 3141: A Type Hierarchy for Numbers

## Abstract

This PEP defines a hierarchy of Abstract Base Classes (ABCs, see PEP 3119) for number-like classes. The hierarchy is:

```
Number :> Complex :> Real :> Rational :> Integral
```

where `A :> B` means "A is a supertype of B". The hierarchy is inspired by Scheme's numeric tower [#schemetower]_.

## Motivation

Python has several numeric types that behave like numbers but share no common base: `int`, `float`, `complex`, and library types such as decimal and fraction classes. [TODO: confirm the list of types the author has in mind.] Code that wants to accept "any real number" has to name each type, and it breaks when a user supplies a new type that behaves like a real number but is not on the list.

An ABC hierarchy addresses this by letting a function ask "is this a `Real`?" instead of "is this an `int` or a `float`?". PEP 3119 supplies the mechanism: `isinstance` checks against an ABC, and registration of classes that do not inherit from it. This PEP uses that mechanism to define which ABCs exist for numbers and how they relate.

## Specification

The hierarchy has five levels, from most general to most specific.

1. `Number`. The root. A class is a `Number` if it represents a number in some sense. The root promises no operations.
2. `Complex`. Numbers that support the arithmetic of the complex field: addition, subtraction, multiplication, division, and negation. [TODO: author to list the exact abstract methods, for example conversion to the builtin `complex`, `real` and `imag` accessors, `conjugate`, and equality.]
3. `Real`. The subset of `Complex` that lies on the real line. A `Real` is ordered. [TODO: author to list the abstract methods, for example comparison, conversion to `float`, and rounding.]
4. `Rational`. The subset of `Real` that is a ratio of two integers. [TODO: abstract attributes, such as `numerator` and `denominator`.]
5. `Integral`. The subset of `Rational` with denominator 1. [TODO: abstract methods, for example conversion to `int` and the bitwise operations.]

The relation `A :> B` means every instance of `B` is also an instance of `A`. Every `Integral` is therefore a `Rational`, a `Real`, a `Complex`, and a `Number`.

The mathematical content of the chain is the usual inclusion of number systems: the integers sit inside the rationals, the rationals inside the reals, and the reals inside the complex numbers. The ABCs follow this chain because a method that works for every `Real` works for every `Integral`, so code written against the general ABC accepts the specific one without change.

## Rationale

### Why a tower

The hierarchy is a tower, a single chain with no branches. The abstract credits Scheme's numeric tower as the inspiration. [TODO: author to say which parts of Scheme's tower were kept and which were dropped. The abstract says "inspired by", so some difference is implied, but none is recorded here.]

A chain has one clear benefit: for any two numeric ABCs, one is a subtype of the other, so the question "which is more general?" always has an answer. It also has a cost. Real numeric types do not always fit a chain. A type may support the ordering of a `Real` but not division, or support division but not ordering. Forcing such a type into the chain means it either claims more than it supports or is left out. ### Why these five levels

Each level matches a body of operations that functions commonly require. `Complex` is the level at which field arithmetic is defined. `Real` adds ordering. `Rational` adds exact numerators and denominators. `Integral` adds integer-only operations. ### What the ABCs do not promise

An ABC states which operations exist. It does not state numerical accuracy. A `float` and a fraction class may both be `Real`, and they give different results for the same expression. ## Examples

The following function accepts any real number and works for user-defined types that register as `Real`:

```python
from numbers import Real

def clamp(x, low, high):
    if not isinstance(x, Real):
        raise TypeError("clamp needs a real number")
    return max(low, min(x, high))
```

Without the ABC, the check would read `isinstance(x, (int, float))` and would reject a fraction type. [TODO: author to confirm the module name `numbers` and that a fraction type registers as `Real`.]

A second example shows the opposite direction. A function that needs exact integer arithmetic checks for `Integral`:

```python
from numbers import Integral

def nth(seq, i):
    if not isinstance(i, Integral):
        raise TypeError("index must be an integer")
    return seq[int(i)]
```
