# PEP 296: Adding a bytes Object Type

## Abstract

This PEP proposes a new standard type, `bytes`, with a builtin constructor of the same name. A `bytes` object stores an array of bytes compactly. It differs from several existing array-of-bytes implementations in the characteristics listed under Specification.

## Motivation

Python programs that handle binary data today have to pick a container that was designed for something else. A program can hold the data in a `str`, which is a string type with text semantics. It can use `array.array('B')`, which is a general numeric array. It can use a `list` of small integers, which stores one object reference per byte. ## Specification

The PEP adds a type `bytes` and a builtin callable `bytes(...)` that constructs instances of it.

A `bytes` object holds a sequence of 8-bit values. Each element is an integer in the range 0 to 255. Storage is contiguous, with one byte per element.

## Rationale

The case for a new type rests on two observations that apply to any container used for raw bytes.

First, the container's type should say what the data is. A `bytes` object cannot be mistaken for text by a reader or by a function that dispatches on type. Second, the container should not charge more than the data requires. A compact array of bytes gives an object whose size is proportional to its length with a small constant.

Both observations argue for a dedicated type. They do not by themselves argue for a new builtin, as opposed to a type in a library module. A builtin constructor adds a name to every program's namespace, and shadowing it breaks code that already defines `bytes`. [TODO: author's reason for choosing a builtin over a library type.
