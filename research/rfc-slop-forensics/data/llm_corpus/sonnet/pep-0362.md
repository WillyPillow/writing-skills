# PEP 362: Function Signature Object

- Status: Draft
- Type: Standards Track
- Python-Version: 3.3

## Abstract

Python has always supported powerful introspection capabilities, including introspecting functions and methods (for the rest of this PEP, "function" refers to both functions and methods). By examining a function object you can fully reconstruct the function's signature. Unfortunately this information is stored in an inconvenient manner, and is spread across a half-dozen deeply nested attributes.

This PEP proposes a new representation for function signatures. The new representation contains all necessary information about a function and its parameters, and makes introspection easy and straightforward.

However, this object does not replace the existing function metadata, which is used by Python itself to execute those functions. The new metadata object is intended solely to make function introspection easier for Python programmers.

## Signature Object

A Signature object represents the call signature of a function and its return annotation. For each parameter accepted by the function it stores a Parameter object in its `parameters` collection.

A Signature object has the following public attributes and methods:

* `return_annotation`: object. The annotation for the return type of the function if specified. If the function has no annotation for its return type, this attribute is set to `Signature.empty`.
* `parameters`: OrderedDict. An ordered mapping of parameters' names to the corresponding Parameter objects.
* `bind(*args, **kwargs)` -> BoundArguments. Creates a mapping from positional and keyword arguments to parameters. Raises a `TypeError` if the passed arguments do not match the signature.
* `bind_partial(*args, **kwargs)` -> BoundArguments. Works the same way as `bind()`, but allows the omission of some required arguments (mimics `functools.partial` behavior).
* `replace(*, parameters=<optional>, return_annotation=<optional>)` -> Signature. Creates a new Signature instance based on the instance `replace` was invoked on. It is possible to pass different parameters and/or return annotation to override the corresponding properties of the base signature. To remove a return annotation from the copied Signature, pass in `Signature.empty`.

Signature objects are immutable. Use `Signature.replace()` to make a modified copy.

Signature objects are picklable and hashable.

### Constructing a Signature

The `Signature` constructor accepts an optional sequence of `Parameter` objects and an optional `return_annotation` keyword argument:

```python
>>> from inspect import Signature, Parameter
>>> p1 = Parameter('a', Parameter.POSITIONAL_OR_KEYWORD)
>>> p2 = Parameter('b', Parameter.KEYWORD_ONLY, default=10)
>>> sig = Signature([p1, p2], return_annotation=int)
>>> str(sig)
'(a, *, b=10) -> int'
```

The constructor validates that parameters appear in a legal order: positional-only parameters first, then positional-or-keyword, then var-positional, then keyword-only, then var-keyword. Within the first two groups, parameters without defaults must precede parameters with defaults. Names must be unique.

### Getting a Signature

The function `inspect.signature(callable)` returns a Signature object for any callable:

```python
>>> def foo(a, b=1, *args, c, **kwargs): pass
>>> sig = inspect.signature(foo)
>>> list(sig.parameters)
['a', 'b', 'args', 'c', 'kwargs']
```

The rules for the several kinds of callable are as follows:

* For a Python function, the signature is built from the function's `__code__`, `__defaults__`, `__kwdefaults__` and `__annotations__` attributes.
* For a bound method, the signature of the underlying function is produced without the first parameter.
* For a class, the signature is derived from its `__init__` method (or `__new__` if `__init__` is not overridden), with the first parameter removed.
* For an instance of a class defining `__call__`, the signature is that of `__call__` with `self` removed.
* For `functools.partial` objects, the signature is that of the wrapped callable, adjusted for the arguments already supplied.
* If the callable has a `__wrapped__` attribute, the signature is taken from the wrapped object, so that decorators written with `functools.wraps` expose the original signature.
* For built-in functions and other callables implemented in C, a `ValueError` is raised if no signature can be determined. This is a limitation of the C API, which does not currently record parameter information in a form that can be introspected.

If the object is not callable, a `TypeError` is raised.

## Parameter Object

Python's expressiveness comes from the variety of ways parameters can be declared. A Parameter object represents one of them. Parameter objects are immutable. Instead of modifying a Parameter object, you can use `Parameter.replace()` to create a modified copy.

Parameter objects have the following public attributes and methods:

* `name`: str. The name of the parameter as a string. Must be a valid python identifier name (with the exception of `POSITIONAL_ONLY` parameters, which can have it set to `None`).
* `default`: object. The default value for the parameter. If the parameter has no default value, this attribute is set to `Parameter.empty`.
* `annotation`: object. The annotation for the parameter. If the parameter has no annotation, this attribute is set to `Parameter.empty`.
* `kind`: one of the following values, named as constants of the Parameter class:
  * `POSITIONAL_ONLY`: value must be supplied as a positional argument. Python has no explicit syntax for defining positional-only parameters, but many built-in and extension module functions (especially those that accept only one or two parameters) accept them.
  * `POSITIONAL_OR_KEYWORD`: value may be supplied as either a keyword or positional argument (this is the standard binding behaviour for functions implemented in Python).
  * `VAR_POSITIONAL`: a tuple of positional arguments that aren't bound to any other parameter. This corresponds to a `*args` parameter in a Python function definition.
  * `KEYWORD_ONLY`: value must be supplied as a keyword argument. Keyword only parameters are those which appear after a `*` or `*args` entry in a Python function definition.
  * `VAR_KEYWORD`: a dict of keyword arguments that aren't bound to any other parameter. This corresponds to a `**kwargs` parameter in a Python function definition.
* `replace(*, name=<optional>, kind=<optional>, default=<optional>, annotation=<optional>)` -> Parameter. Creates a new Parameter instance based on the instance `replace` was invoked on. To override a Parameter attribute, pass the corresponding argument. To remove an attribute, pass `Parameter.empty`.

The `Parameter.empty` and `Signature.empty` sentinels are classes, not instances, so that they can be pickled and are distinguishable from legitimate values such as `None`, which is a valid default and a valid annotation.

Parameter objects are hashable and comparable. Two parameters are equal when their name, kind, default and annotation are equal.

Beware of the case of keyword-only and default parameters in the string form: `str(Parameter)` is the text that could appear in a `def`, such as `b:int=10`.

## BoundArguments Object

Result of a `Signature.bind` call. Holds the mapping of arguments to the function's parameters.

Has the following public attributes:

* `arguments`: OrderedDict. An ordered, mutable mapping of parameters' names to arguments' values. Contains only explicitly bound arguments. Changes in `arguments` will reflect in `args` and `kwargs`.
* `args`: tuple. Tuple of positional arguments values. Dynamically computed from the `arguments` attribute.
* `kwargs`: dict. Dict of keyword arguments values. Dynamically computed from the `arguments` attribute.

The `args` and `kwargs` properties can be used to invoke functions:

```python
def test(a, *, b):
    ...

sig = signature(test)
ba = sig.bind(10, b=20)
test(*ba.args, **ba.kwargs)
```

Arguments which could be passed as part of either `*args` or `**kwargs` will be included only in the `BoundArguments.args` attribute. In the following example:

```python
def test(a=1, b=2, c=3):
    pass

sig = signature(test)
ba = sig.bind(a=10, c=13)
```

`ba.args` is `(10,)`? No: only those leading arguments that were explicitly bound are included, and since `b` was not bound, binding stops there. Hence `ba.args` is `(10,)` and `ba.kwargs` is `{'c': 13}`.

## Implementation

The implementation adds the classes `Signature`, `Parameter` and `BoundArguments` and the function `signature()` to the `inspect` module. A pure Python implementation is possible, since all of the information is available from the function's existing attributes and `__code__` object. For a function `f`:

1. `f.__code__.co_varnames` supplies the parameter names, in order, up to `co_argcount`, followed by the keyword-only names up to `co_kwonlyargcount`, then the names of `*args` and `**kwargs` if the flags `CO_VARARGS` and `CO_VARKEYWORDS` are set.
2. `f.__defaults__` supplies defaults for the last `n` positional-or-keyword parameters.
3. `f.__kwdefaults__` supplies the defaults for the keyword-only parameters.
4. `f.__annotations__` supplies annotations, keyed by name, with the return annotation under `'return'`.

The implementation caches nothing, since signatures can be changed by assigning to the function's attributes.

## Design Considerations

### No implicit caching or storage on the function

An alternative would be to attach a `__signature__` attribute to every function at creation. This would increase the memory footprint of every function object, and Python functions already carry enough information to construct one. However, `inspect.signature()` honors an explicit `__signature__` attribute if one is set on an object, so that decorators, builtin wrappers and C extension types can supply a signature when the automatic approach would not work.

### Positional-only parameters

Since Python syntax cannot declare positional-only parameters, the representation exists purely to describe C functions. Hence the `name` may be `None` for these. Proposals to add syntax are outside the scope of this PEP.

### Annotations

Annotations are stored as they are, with no evaluation or interpretation. Their meaning is left to the consumer.

## Examples

A decorator that checks calls against the signature:

```python
def check_args(func):
    sig = signature(func)
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        sig.bind(*args, **kwargs)
        return func(*args, **kwargs)
    return wrapper
```

A function that adds a keyword-only parameter to a signature:

```python
def add_flag(sig, name):
    params = list(sig.parameters.values())
    params.append(Parameter(name, Parameter.KEYWORD_ONLY, default=False))
    return sig.replace(parameters=params)
```
