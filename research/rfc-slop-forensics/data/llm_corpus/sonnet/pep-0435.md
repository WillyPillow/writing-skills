# PEP 435: Adding an Enum type to the Python standard library

- Status: Draft
- Type: Standards Track
- Python-Version: 3.4

## Abstract

This PEP proposes adding an enumeration type to the Python standard library. An enumeration is a set of symbolic names bound to unique, constant values. Within an enumeration, the values can be compared by identity, and the enumeration itself can be iterated over.

## Motivation

Python has no built-in way to define a group of related named constants. Programmers currently use several idioms, each with shortcomings.

The most common is a set of module-level or class-level integer constants:

```python
class Color:
    RED = 1
    GREEN = 2
    BLUE = 3
```

This is simple, but the values are plain integers. They print as numbers, they compare equal to any other integer with the same value, and they may be used in arithmetic where it makes no sense: `Color.RED + Color.BLUE` is `4`, which is no color at all. Nothing groups the members, so there is no way to ask "what are all the colors?" without inspecting the class dictionary and filtering out unrelated attributes. Two unrelated sets of constants can also compare equal: `Color.RED == Animal.DOG` is true if both happen to be `1`.

Other idioms include strings, tuples, and custom classes built with metaclass tricks. A number of third-party packages exist for this purpose, and a variety of recipes have circulated for years. The existence of so many independent implementations indicates both demand and a lack of agreement on design. Standardizing one in the standard library gives users a common vocabulary, enables other libraries to depend on it, and lets tools such as debuggers and documentation generators recognize enumerations.

## Rationale

The design here is based on the common features found in the existing implementations, while keeping the interface small enough that it can be taught in a few minutes.

An enumeration should have these properties:

* Members have a readable name, and a readable representation.
* Members are singletons; comparing members is done by identity.
* Members are hashable and may be used as dictionary keys.
* The enumeration is iterable, and iteration order is definition order.
* Members of different enumerations are never equal, even if their underlying values are.
* The set of members is fixed once the class is created. Members cannot be added, removed or rebound.

## Specification

### Creating an Enum

Enumerations are created using the `class` syntax, which makes them easy to read and write. An enumeration is defined by subclassing `Enum`:

```python
from enum import Enum

class Color(Enum):
    red = 1
    green = 2
    blue = 3
```

The class `Color` is an enumeration, and `Color.red`, `Color.green` and `Color.blue` are its members. Members have a `name` and a `value`:

```python
>>> Color.red
<Color.red: 1>
>>> str(Color.red)
'Color.red'
>>> Color.red.name
'red'
>>> Color.red.value
1
>>> type(Color.red)
<enum 'Color'>
>>> isinstance(Color.red, Color)
True
```

Members can be looked up by value, using call syntax, or by name, using item access:

```python
>>> Color(1)
<Color.red: 1>
>>> Color['green']
<Color.green: 2>
```

Looking up a value that does not exist raises `ValueError`; looking up an unknown name raises `KeyError`.

### Iteration and ordering

An enumeration is iterable, and members are produced in the order in which they were defined:

```python
>>> list(Color)
[<Color.red: 1>, <Color.green: 2>, <Color.blue: 3>]
```

Members can be compared by identity and by equality, and equality is identity:

```python
>>> Color.red is Color.red
True
>>> Color.red == Color.blue
False
```

Ordered comparisons such as `<` are not supported by plain `Enum` members, because the order of symbolic names generally has no meaning. Attempting to use them raises `TypeError`. Equality comparison against non-enum values returns `False`; an `Enum` member is not equal to its underlying value.

### Aliases

If two names are given the same value, the second name is an alias for the first:

```python
class Shape(Enum):
    square = 2
    diamond = 1
    circle = 3
    alias_for_square = 2
```

`Shape.alias_for_square is Shape.square` is true. Aliases are not produced during iteration; only the canonical member is. A special attribute, `__members__`, maps every name, including aliases, to its member in an ordered mapping, and may be used to find them.

### Uniqueness

A class decorator, `@unique`, is provided for those who wish to disallow aliases. If a decorated enumeration has a duplicate value, `ValueError` is raised at class creation time.

### Immutability

Attributes of an enumeration class cannot be rebound once it is created, and members cannot be deleted. A subclass of an enumeration with members cannot be created. This is important: a subclass would introduce new members that are not part of the original set, violating the closed-world property. Subclassing is permitted only when the base enumeration defines no members, which allows common behaviour to be shared through a mixin.

### Methods and attributes

Enumerations are classes and may define methods:

```python
class Planet(Enum):
    mercury = (3.303e+23, 2.4397e6)
    earth = (5.976e+24, 6.37814e6)

    def __init__(self, mass, radius):
        self.mass = mass
        self.radius = radius

    @property
    def surface_gravity(self):
        G = 6.67300E-11
        return G * self.mass / (self.radius * self.radius)
```

When the value is a tuple, it is unpacked and passed to `__init__`. Methods and descriptors defined in the class body are not treated as members. Names starting and ending with a double underscore are likewise ignored, as are names beginning with a single underscore which are reserved for the implementation.

### IntEnum

For cases where members must interoperate with integers, such as when wrapping constants from a C library, a variant `IntEnum` is provided. Its members are subclasses of `int`, and so compare equal to integers and support ordering:

```python
>>> from enum import IntEnum
>>> class Priority(IntEnum):
...     low = 1
...     high = 2
>>> Priority.low < Priority.high
True
>>> Priority.low == 1
True
```

Because this violates the principle that enumeration members are not integers, it is intended to be used only when compatibility is needed. Members of two different `IntEnum` classes still compare equal if their integer values do, which is a consequence of being integers.

### Functional API

For dynamic creation of enumerations, a functional API is available:

```python
>>> Animal = Enum('Animal', 'ant bee cat dog')
>>> Animal.cat
<Animal.cat: 3>
```

The first argument is the class name, and the second is the member names, given as a whitespace or comma separated string, a sequence of names, or a sequence of `(name, value)` pairs. If no values are given, they are numbered from 1. The module of the new class is determined by inspecting the calling frame, and pickling of such classes works if this succeeds. An optional `module` argument can be passed when frame inspection is not possible.

### Pickling and copying

Members are pickled by reference to their class and name, and so unpickling returns the singleton. Copying an enumeration member returns the same object.

### Implementation

The `Enum` class is implemented by the metaclass `EnumMeta`. Its `__prepare__` method returns a special dictionary that records definition order, and detects reuse of a name within the class body, which raises `TypeError`. The metaclass then builds the members from the recorded names, creating one instance of the class for each unique value.

## Interactions with other features

Enumeration members may be used as dictionary keys and in sets. They are usable in `match`-like constructions built with `if/elif` and `is`, which is the recommended way to dispatch on a member.

Because members are objects and not integers, passing one to a function expecting an integer, such as `range()`, fails unless the enumeration derives from `IntEnum`. This is intentional.

## Alternatives considered

**A new syntax.** Some languages provide an `enum` keyword. A language change was rejected because the class syntax gives all the necessary expressiveness, and a library solution does not require changes to the grammar, the compiler or other implementations.

**Auto-numbering by default.** Several packages assign values automatically. This PEP requires explicit values in the class syntax, which is more explicit and makes the values stable when members are reordered. Auto-numbering is available through the functional API.

**Allowing ordered comparisons by default.** This was rejected because most enumerations are categorical and ordering would be arbitrary. Users who want ordering can use `IntEnum` or define comparison methods.

**Using strings as the canonical representation.** This does not provide any grouping or protection against comparing unrelated constants.

## Backwards compatibility

This PEP adds a new module and does not change existing behaviour. The name `enum` does not conflict with anything in the standard library. A third-party package named `enum` exists on the Python Package Index, and users who have it installed may encounter shadowing; a backport with a different name is planned for earlier Python versions.

## Open issues

* Whether the default `repr` should include the value, or only the name.
* Whether `__members__` should be exposed as a read-only mapping proxy.
* Whether an `auto()` helper for assigning values within the class body should be provided in a later version.
