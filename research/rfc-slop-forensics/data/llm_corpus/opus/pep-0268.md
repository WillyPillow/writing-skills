# Abstract

This PEP discusses new modules and extended functionality for Python's HTTP support. Notably, it proposes the addition of authenticated requests, proxy support, authenticated proxy usage, and WebDAV capabilities.

# Rationale

Python has included `httplib` for some time, and `urllib`/`urllib2` provide higher-level access to URLs. These modules handle the common case of fetching a resource well, but they leave significant gaps for applications that use HTTP as a general-purpose protocol rather than simply as a way to download pages:

- **Authentication.** `httplib` has no support for HTTP authentication. Applications that need Basic authentication must construct the `Authorization` header by hand, and Digest authentication — the only one of the two that does not send passwords in the clear — is not supported at all.
- **Proxies.** `urllib` supports proxies for simple requests, but `httplib` does not. Applications that use `httplib` directly, which includes any application that needs methods other than GET and POST, cannot work through a proxy without reimplementing the request logic.
- **Authenticated proxies.** Corporate networks commonly require authentication at the proxy. No Python module handles `407 Proxy Authentication Required` responses.
- **WebDAV.** RFC 2518 defines Web Distributed Authoring and Versioning, a set of HTTP extensions for managing resources on a server: creating collections, copying and moving resources, locking, and storing arbitrary properties. WebDAV is implemented by Apache's `mod_dav`, Microsoft IIS, and a growing number of document management systems. Python has no client support for it.

These features are closely related. Authentication and proxy handling must be integrated at the connection level so that every request benefits, and WebDAV is built entirely on top of HTTP requests that need both. It makes sense to address them together.

# Specification

The work is divided into three parts: extensions to `httplib`, a new `davlib` module, and integration with `urllib2`.

## HTTP Authentication

`httplib` gains an authentication layer that responds to `401 Unauthorized` and `407 Proxy Authentication Required` responses.

### Authentication handlers

An authentication handler is an object with the following interface:

```python
class AuthHandler:
    def get_credentials(self, realm, uri, proxy=0):
        """Return (username, password) or None."""
```

The connection calls `get_credentials` when the server issues a challenge. A handler may look up credentials from a dictionary, prompt the user interactively, or consult a password manager. Returning `None` means no credentials are available, and the 401 or 407 response is returned to the caller as is.

A simple default implementation is provided:

```python
class PasswordManager:
    def add_password(self, realm, uri, user, passwd): ...
    def get_credentials(self, realm, uri, proxy=0): ...
```

Credentials are matched by realm and by URI prefix, so that a single entry covers an entire subtree of a server.

### Authentication schemes

Two schemes are supported:

- **Basic** (RFC 2617): the username and password are base64-encoded and sent in the `Authorization` header. This is insecure over unencrypted connections and should be used only over HTTPS, but it is widely deployed.
- **Digest** (RFC 2617): the client computes an MD5 hash over the credentials, a server-supplied nonce, and the request, so the password is never transmitted. The `auth` quality-of-protection option is supported; `auth-int` is optional.

Scheme handling is pluggable through a registry, so that additional schemes (for example, NTLM, which some corporate proxies require) can be added by third-party modules without changes to `httplib`.

### Retrying requests

When a challenge is received, the connection obtains credentials, computes the appropriate header, and reissues the request. If the request has a body, the body must be resent. For bodies supplied as strings, this is straightforward. For bodies supplied as file-like objects, the object must support `seek`; if it does not, the challenge response is returned to the caller.

After a successful authentication, the connection remembers the scheme and credentials for the realm, and preemptively sends the `Authorization` header on subsequent requests to the same protection space. This avoids an extra round trip per request.

## Proxy Support

`HTTPConnection` gains optional proxy arguments:

```python
conn = httplib.HTTPConnection(host, port,
                              proxy_host="proxy.example.com",
                              proxy_port=8080)
```

When a proxy is configured, the connection is made to the proxy, and request lines use the absolute URI form (`GET http://host/path HTTP/1.1`) as required by RFC 2616.

For HTTPS through a proxy, the connection issues a `CONNECT host:port` request to the proxy, waits for a `200` response, and then performs the SSL handshake over the tunnelled connection.

### Authenticated proxies

Proxy authentication uses the same handler interface, with `proxy=1` passed to `get_credentials`. The resulting credentials are sent in the `Proxy-Authorization` header. A connection may have both proxy and origin server credentials at the same time, handled independently.

### Environment configuration

If no proxy is specified, the connection does not consult environment variables by default; this preserves the existing low-level behaviour of `httplib`. The higher-level `urllib2` integration (below) honours the conventional `http_proxy`, `https_proxy`, and `no_proxy` variables.

## WebDAV: the `davlib` module

A new module, `davlib`, provides a client for WebDAV servers. It is built on the extended `httplib` and therefore supports authentication and proxies automatically.

### Connection class

```python
class DAVConnection(httplib.HTTPConnection):
    def propfind(self, url, depth=0, props=None): ...
    def proppatch(self, url, set_props=None, remove_props=None): ...
    def mkcol(self, url): ...
    def copy(self, src, dst, depth="infinity", overwrite=1): ...
    def move(self, src, dst, overwrite=1): ...
    def lock(self, url, owner, depth=0, timeout=None, scope="exclusive"): ...
    def unlock(self, url, token): ...
    def delete(self, url): ...
    def put(self, url, body, content_type=None): ...
    def get(self, url): ...
```

Each method constructs the appropriate request, including the XML request body for `PROPFIND`, `PROPPATCH`, and `LOCK`, sends it, and returns a response object.

### Responses

WebDAV methods often return `207 Multi-Status`, an XML document containing a separate status for each affected resource. The module parses this into a structure that maps each resource URL to its status and properties:

```python
response = conn.propfind("/docs/", depth=1, props=["getcontentlength", "getlastmodified"])
for href, result in response.items():
    print href, result.status, result.props["getlastmodified"]
```

Properties are identified by `(namespace, name)` pairs; the `DAV:` namespace may be omitted for convenience. Property values are returned as strings for simple properties and as XML element objects for structured ones.

The XML parsing uses the `xml.dom.minidom` or `xml.parsers.expat` modules already in the standard library, so no new dependencies are introduced.

### Locking

`lock` returns a lock token, which the caller passes to subsequent requests via an `If` header. The connection can optionally track tokens it has acquired and supply them automatically to requests against locked resources.

## Integration with `urllib2`

`urllib2` gains handlers built on the above: `HTTPDigestAuthHandler` and `ProxyDigestAuthHandler`, alongside improvements to the existing Basic handlers. These make the new functionality available to applications that use `urlopen` without code changes beyond installing an opener.

# Backwards Compatibility

All additions are optional. Existing code that uses `httplib` without proxy or authentication arguments behaves exactly as before. In particular, automatic retry on 401 only occurs when an authentication handler has been installed on the connection.

# Security Considerations

Basic authentication sends passwords in a recoverable form. The documentation will recommend Digest authentication or HTTPS. The library will not downgrade from Digest to Basic if a server offers both.

Preemptive authentication must be limited to the protection space in which it was established, so that credentials are not sent to unrelated servers after a redirect.

- Should `httplib` handle redirects internally, or leave that to `urllib2`?
