# PEP 450: Adding a statistics module to the standard library

- **Type:** Standards Track
- **Status:** Final

## Abstract

This proposal adds a module to the standard library that provides the common descriptive statistics functions a programmer is likely to need. The first version includes the arithmetic mean, the median and its variants, the population and sample variance, and the matching standard deviations. The module is designed to give correct results for ordinary data without requiring the user to understand floating point rounding, and it is written so that it can later be extended with more advanced estimators.

The name of the module is `statistics`. Its functions accept any iterable of numbers and return results that follow the type of the input where that is sensible. A reference implementation is available, and a discussion thread records the choices made during review.

## Motivation

Python is widely used for data analysis, but its standard library has never included a statistics module. Programmers who need the mean of a list must write a loop or import a third-party package. Those who need the median must sort the data and handle the even-length case themselves, which is easy to get wrong. The variance is more subtle still, and naive formulas can lose most of their precision when the data have a large mean and a small spread.

These are problems that nearly every program that handles numbers will meet at some point. A standard module would remove the need for many small helper functions and would give a single, well-tested definition of each quantity. It would also make the language more attractive for teaching, because the examples in introductory courses could rely on the library rather than on custom code.

The more ambitious libraries in the scientific Python ecosystem offer much more, but they are large dependencies. The standard library needs only the basic functions, implemented carefully.

## Specification

The module provides the following functions in its first version.

`mean(data)` returns the arithmetic mean of a non-empty iterable. The result is computed exactly when the inputs are integers or fractions, and with the best available precision for floats.

`median(data)` returns the middle value of a sorted copy of the data. For an even number of values it returns the average of the two central values. A variant, `median_low`, returns the lower of the two central values, and `median_high` returns the upper one. These variants are useful when the result must be one of the input values.

`variance(data, xbar=None)` and `pvariance(data, mu=None)` return the sample variance and the population variance. The optional argument allows the caller to supply a mean that has already been computed, which avoids a second pass over the data.

`stdev(data, xbar=None)` and `pstdev(data, mu=None)` return the square roots of the corresponding variances.

Each function raises `StatisticsError` when the input is empty, or when the requested quantity is undefined, such as the sample variance of a single value.

## Numerical accuracy

The most important design decision concerns accuracy. Floating point arithmetic can give noticeably wrong answers for mean and variance when the values are large in magnitude but close together. A familiar example is a set of values near one billion whose spread is only a few units. A naive sum of squares loses most of its significant digits in this case.

The proposal therefore calls for the module to compute intermediate sums using exact rational arithmetic where the input allows it, and to use a stable two-pass method for variance when the input is floating point. Exact computation is slower, so the implementation converts the input to fractions only when needed, and it documents the cost.

For inputs that mix integers, fractions, and floats, the module converts each float to an exact fraction before summing. This gives the correctly rounded answer for the sum, which is then divided by the count. The result is returned as a float unless all the inputs were exact.

## Rationale

The decision to use exact arithmetic in the first version reflects a judgement that correctness is more important than speed for a library of this kind. Users who need speed for very large data sets can use a specialised package, while users who need an answer they can trust get one from the standard library.

Keeping the functions to a small set was intentional. Statistical practice contains many estimators, and choosing among them requires judgement about the data. The proposal limits the first version to quantities that have a single widely accepted definition. Others can be added in later releases with their own discussion.

The optional arguments that accept a precomputed mean are a concession to performance. Callers that already know the mean can avoid one pass over the data, and the optional argument makes this explicit without complicating the default call.

## Naming

The name `statistics` was chosen after discussion. Shorter names were considered, but they risked clashing with local variables in user code. The function names follow those of the commonly used third-party libraries, so that people moving between them will find familiar names.

## Backwards Compatibility

The module is new, so there are no existing users to affect. Any existing code that defines functions with the same names keeps working, because the module is imported explicitly.

## Reference Implementation

The reference implementation is written in pure Python and uses the `fractions` module for exact arithmetic. It is designed to be readable, so that reviewers can check the algorithm against the mathematical definitions. Performance measurements were taken and are recorded in the discussion. The implementation is expected to be replaced by a faster version over time, but the interface will not change.

## Open Issues

Some reviewers asked for more functions, including ways to compute quantiles with several different definitions, and for correlation and regression. The proposal does not include them. It notes that quantile definitions differ between textbooks, and that a choice made in the standard library would be hard to change later.

A second question concerns the return type of `mean` when the input is an empty iterator. The draft raises an error, but a few participants preferred a default value. The error is kept because a silent default would hide mistakes.

## Summary

The proposal adds a `statistics` module with mean, median, variance, and standard deviation. It emphasises correct results through exact arithmetic and stable algorithms, and it keeps the first version small so that the design can be reviewed carefully. The module fills a gap that many programmers currently fill with their own code, and it gives a single trustworthy definition for each function.
