PEP: 485
Title: A Function for testing approximate equality
Author: Chris Barker <chris.barker@noaa.gov>, Nathaniel Smith <njs@pobox.com>
Status: Final
Type: Standards Track
Created: 2015-01-20
Python-Version: 3.5
Post-History: 2015-01-20

Abstract
========

This PEP proposes the addition of an ``isclose()`` function to the standard library ``math`` module. The function determines whether one value is approximately equal, or "close", to another value. The function is intended for use in tests, in numerical code, and in any situation where two floating point results are expected to agree within some tolerance but are not expected to be exactly equal.

Motivation
==========

Floating point arithmetic is inexact. A result computed by a sequence of operations is usually not the same as the mathematically exact value, and two computations that should agree may differ in their last few bits. Testing for exact equality in such cases is almost always a mistake, and programmers who write it discover the problem when a test fails for a reason that is not visible in the code.

The standard practice is to compare the difference between two values with a tolerance. The difference is computed, and it is accepted if it is smaller than the tolerance. This approach is simple, but it is easy to get wrong. The tolerance can be absolute or relative, and the choice matters a great deal when the values are very large or very small. A comparison of two values near zero using a purely relative tolerance will always fail, while a comparison of two very large values using a purely absolute tolerance will be too strict.

Many programmers write their own helper functions, and many of those helpers are wrong in some edge case. Numerical libraries provide their own versions, but the standard library does not, and the functions available in the standard library for testing values, such as the unit test assertion methods, do not provide a relative tolerance.

A function in the ``math`` module would give everyone a common, documented, and tested tool.

Rationale
=========

The function takes two floating point values and two tolerance parameters. It returns true if the values are close according to either tolerance. The first tolerance is relative, and it is the fraction of the larger of the two magnitudes. The second tolerance is absolute, and it is a fixed bound on the difference.

Using both tolerances is necessary. A relative tolerance alone fails when one of the values is zero, because the relative difference is then undefined in a meaningful sense. An absolute tolerance alone fails when the values are large, because a fixed bound that is reasonable for values near one is too strict for values near a million. The combination covers both regimes.

The default relative tolerance is set to nine decimal digits. This is a conservative value. It accepts values that differ in their last few bits, which is the typical result of rounding in a short sequence of operations, while rejecting values that differ in a meaningful digit. The default absolute tolerance is zero. This means that the function does not accept a difference near zero by default, and the caller must explicitly ask for an absolute tolerance if one is needed.

The function treats the case of two infinite values, or two values that are both NaN, with explicit rules. Two infinities of the same sign are close to each other. A NaN is not close to any value, including itself. These rules match the usual behaviour of comparisons in IEEE arithmetic and make the function predictable.

Specification
=============

The function has the signature ``isclose(a, b, *, rel_tol=1e-09, abs_tol=0.0)``. The two positional arguments are the values to compare. The two keyword-only arguments are the relative and absolute tolerances. Both tolerances must be nonnegative, and a negative tolerance raises a ValueError.

The function returns True if the absolute difference between the values is less than or equal to the larger of the two tolerances scaled appropriately. More precisely, the values are close if the difference is at most the relative tolerance times the larger magnitude of the two values, or at most the absolute tolerance. The comparison is symmetric, so that ``isclose(a, b)`` and ``isclose(b, a)`` always agree.

The function accepts any value that can be converted to a float. Integers are converted exactly where possible, and very large integers are converted with the usual rounding rules of the float type.

Implications for testing
========================

The most common use of the function is in unit tests. A test that compares a computed result with an expected value can call ``isclose()`` and receive a clear boolean answer, without the need to write the tolerance logic each time. The test then reads more clearly, and its intent is visible to a reader.

The function is also useful in numerical code that makes decisions based on comparisons of computed values. Such code often needs to decide whether two values are the same for the purposes of a convergence test or a branch. The function provides a consistent answer, and the tolerances are visible in the call.

Design discussion
=================

Several alternatives were considered during the discussion. One was to provide a function that compares only with a relative tolerance and to leave the absolute case to the caller. This was rejected because the absolute case is common enough that users would otherwise write it themselves, and they would often write it wrongly.

Another alternative was to use a default absolute tolerance that is not zero. This was rejected because any nonzero default would silently accept values that differ meaningfully when they are small, and the authors judged that the caller should have to choose.

A third alternative was to name the function differently, such as ``approx_equal``. The name ``isclose`` was chosen because it is consistent with the naming of similar functions in other languages and libraries, and because it describes the result as a property of the two values rather than as a claim about equality.

There was also a discussion about whether the function should be in the ``math`` module or in a separate module for testing. The ``math`` module was chosen because the function is numerical in nature and because the module already contains functions that are similar in spirit.

Backwards compatibility
=======================

The function is new and does not change any existing behaviour. No existing code depends on it, and no existing name is affected.

Reference implementation
========================

A reference implementation is provided in the form of a Python function that uses only the basic operations of the language. It has a suite of tests that cover the cases described in this document, including zero, very large and very small values, infinities, NaN, and negative tolerances. A C implementation is possible and may be added later for speed.

Open issues
===========

The default relative tolerance is a judgement, and some users may prefer a different value. The authors chose nine decimal digits as a compromise, and they recognize that the choice is a matter of taste as much as of technical analysis.

The behaviour of the function for very small subnormal values needs a careful check, because the relative tolerance may be large compared with the values being compared. The reference implementation handles the common cases, and the remaining cases should be documented.
