PEP: 616
Title: String methods to remove prefixes and suffixes
Author: (to be assigned)
Status: Draft
Type: Standards Track
Created: (to be assigned)
Python-Version: 3.9

Abstract
========

This proposal adds two methods, ``removeprefix()`` and ``removesuffix()``, to the string types of the language. Each method removes a prefix or suffix from a string if the string begins or ends with it, and otherwise returns the string unchanged. The methods are added to ``str``, to the binary types ``bytes`` and ``bytearray``, and to ``collections.UserString``, so that all text and byte-oriented sequences offer the same operation.

Motivation
==========

Removing a known prefix or suffix is among the most common operations in string processing. Programs strip file extensions, remove URL schemes, drop a leading marker from a line, and trim a fixed tail from a generated name. Python programmers have long performed these tasks with slicing and a length check, or with the ``lstrip`` and ``rstrip`` methods. Both approaches have pitfalls.

Slicing requires the programmer to compute the length of the prefix and to check that the string actually begins with it, and the two steps are easy to write inconsistently. A suffix removal written as ``s[:-len(suffix)]`` is incorrect when the suffix is empty, because the slice then discards every character. Many programs contain this latent defect.

The strip methods are a different tool. ``lstrip`` and ``rstrip`` remove any combination of the characters in their argument, not the argument as a whole. A call such as ``"Arthur".lstrip("Ar")`` produces ``"thur"``, which surprises almost everyone who reads it. The confusion is common enough that it appears in beginner guides and in production code alike.

A pair of methods that remove an exact prefix or suffix, and that behave as their names promise, would remove both hazards. The new methods take a single argument, interpret it literally, and return the input unchanged when it does not match.

Specification
=============

The method ``str.removeprefix(prefix)`` returns the string with the prefix removed, if the string starts with the prefix. If the string does not start with the prefix, the method returns the string unchanged. The method ``str.removesuffix(suffix)`` behaves in the same way at the end of the string.

When the argument is the empty string, both methods return the original string. This rule is consistent with the mathematical meaning of an empty prefix and avoids the defect described above.

The same behavior applies to ``bytes`` and ``bytearray``, where the argument must be a bytes-like object. For ``bytearray``, the method returns a new object rather than modifying the original, which matches the convention of the other methods on the type. The ``UserString`` class in the ``collections`` module gains the same methods, implemented in terms of the wrapped string.

Each method returns a value of the same type as its receiver. Passing a non-string argument to ``str.removeprefix`` raises ``TypeError``, as do the existing string methods.

Rationale
---------

The method names were chosen to be descriptive and to match the vocabulary of the existing ``startswith`` and ``endswith`` methods. The design deliberately avoids an optional second argument or a keyword flag, because the single-purpose form is easier to read and to document.

An alternative was to add a function to the ``string`` module. This would separate the operation from the objects it operates on and would not help code that already holds a string value. Methods on the types themselves are more discoverable and more natural to use in chained expressions.

Backwards Compatibility
=======================

Adding methods to a type can break code that defines a subclass with a conflicting method of the same name. The chosen names are unlikely to collide with existing methods, and the draft found no conflicts in a survey of popular third-party packages. Code that already uses the slicing idiom is unaffected, and it may be rewritten at the author's convenience.

The change is additive and does not alter any existing method. Programs that do not call the new methods behave exactly as before.

Reference Implementation
========================

The reference implementation adds the methods in C for the built-in types and in Python for ``UserString``. The C implementation performs the prefix or suffix comparison directly on the underlying buffer, without allocating an intermediate object when the argument does not match. When the match succeeds, the implementation returns a slice of the original buffer, so the cost is proportional to the length of the result.

Tests cover the empty argument, arguments longer than the string, arguments that match in part, and non-string arguments. The test suite also checks that the methods behave identically across the supported string types.

Documentation
-------------

The documentation for the string methods gains entries for both new methods, placed alongside ``startswith`` and ``endswith``. The entries include short examples that contrast the new methods with the strip methods, since the confusion between them is the most common source of error.

Open Issues
===========

The draft does not define behavior for a prefix or suffix that is a tuple of alternatives, as the ``startswith`` method allows. Such an extension could be added later, but it would complicate the simple contract that the methods currently provide, so it is omitted for now.
