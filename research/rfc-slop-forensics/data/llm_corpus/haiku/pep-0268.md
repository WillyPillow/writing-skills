PEP: 268
Title: Extended HTTP functionality and WebDAV
Author: Greg Stein
Status: Deferred
Type: Standards Track
Content-Type: text/x-rst
Created: 2000-11-01
Python-Version: 2.2

Abstract
========

This PEP discusses new modules and extended functionality for Python's HTTP support. Notably, it proposes the addition of authenticated requests, proxy support, authenticated proxy usage, and WebDAV capabilities. The proposal aims to bring the HTTP client facilities of the standard library closer to the expectations of programmers who write network software, while keeping the public interface simple and consistent with the rest of the library.

Motivation
==========

The HTTP client code in the standard library at this time was limited. It could issue simple requests and read responses, but it provided little support for common needs. Many sites required authentication before they would serve a resource, and the library had no direct way to supply credentials. Organizations that accessed the web through a proxy had to configure environment variables or write custom code, and proxies that themselves required authentication were not supported at all.

WebDAV, a set of extensions to HTTP for authoring and managing resources on a server, was also becoming important. Programmers who wanted to manage files on a remote server through the protocol had to write the request formatting by hand. A library that understood the extensions would make such tasks straightforward and would reduce the number of errors in hand-built requests.

The PEP argues that these needs are common enough that they belong in the standard library, rather than in third-party packages that users must discover and install.

Proposal
========

The proposal adds support for several features to the HTTP client modules.

Authenticated requests are supported through a handler that can supply credentials when a server responds with an authentication challenge. The handler supports the basic and digest schemes, and it retries the request with the appropriate header when a challenge is received. Credentials are stored in a password manager object, which allows a program to supply different credentials for different realms and hosts.

Proxy support is added through a handler that directs requests to a configured proxy server. The configuration may be given explicitly, or it may be read from the environment in the usual way. The handler supports both plain and secure requests, and it uses the proxy's address to open the connection rather than the target's address.

Authenticated proxy usage combines the two previous features. A proxy that requires credentials receives them in the appropriate header, and the handler retries the request when the proxy issues a challenge. The design reuses the password manager, so that a single set of credentials can serve both the proxy and the origin server when appropriate.

WebDAV support is provided through a set of methods that build the standard WebDAV requests, such as the methods for listing a collection, creating a collection, and copying or moving a resource. The methods return the response in a form that is consistent with the rest of the HTTP interface, so that programs do not need to parse the protocol themselves.

Design Notes
============

The handlers are designed to be chained. A program may install several handlers, and each handler is given the opportunity to process a request or a response. This follows the design of the existing URL handling code, and it keeps each feature independent of the others.

The authentication handler does not send credentials on the first request to a server. It waits for a challenge, so that credentials are not disclosed to servers that do not require them. The PEP considers this an important security property and asks that it be preserved in any implementation.

The WebDAV methods do not attempt to implement the full protocol. They cover the requests that are most commonly needed, and they leave the more specialized parts, such as locking, to later work.

Backwards Compatibility
=======================

The proposal adds new handlers and methods. It does not change the behavior of existing functions, so programs that use the current interface will continue to work unchanged. Programs that want the new features must opt in by installing the handlers or calling the new methods.

Security Considerations
=======================

Credentials handled by the authentication code must not be sent over an insecure channel unless the user has explicitly allowed it. The PEP recommends that the library warn when credentials would be sent without encryption. Proxy credentials require similar care, because a compromised proxy could observe them.

Open Issues
===========

The PEP does not settle whether the digest scheme should be included in the first version, given that its security properties were still being studied at the time. It also leaves open the question of how much of the WebDAV specification should be covered, and whether the library should expose a high-level interface for common file operations built on top of the methods.

Reference Implementation
========================

A prototype implementation was written as an extension to the existing HTTP modules. It demonstrated that the handlers could be chained without changing the core request code, but it was not yet complete at the time the PEP was written.
