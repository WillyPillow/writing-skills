# PEP 327: Decimal data type

## Abstract

This PEP proposes a `Decimal` data type for every use where decimal numbers are needed but binary floating point is too inexact. `Decimal` supports the Python standard functions and operations, and must comply with the decimal arithmetic standard ANSI X3.274-1996 [1].

`Decimal` is a floating-point type, not a fixed-point type, and has bounded precision: the precision is the upper limit on the number of significant digits in a result. The precision is set by the user, and trailing zeros are significant, so the type can also be used for fixed-point work.

The work is based on code and test functions written by Eric Price, Aahz and Tim Peters. Just before Python 2.4a1, the `decimal.py` reference implementation was moved into the standard library.

## Motivation

Python's `float` stores a number as a binary fraction. Most decimal fractions have no exact binary representation, so the value a program stores differs from the value it was written with:

```python
>>> 0.1 + 0.2 == 0.3
False
```

The difference is small, but it is not the difference a person computing by hand would get. For a program that handles money, the gap is a correctness problem. A sum of prices must match the sum on the invoice to the cent, and a rounding rule set by law or contract must be applied to a decimal value, not to a nearby binary one.

Programs that need decimal results today have two workarounds. They can store integer counts of the smallest unit, such as cents, and convert at the edges. This works until a calculation needs a finer unit, such as a tax rate applied to a price, and the program must then track the scale of each value by hand. Or they can use `float` and round at the end, which gives the right answer in most cases and the wrong answer in a few, without saying which.

## Requirements

The type must meet these requirements, which come from the abstract:

1. Represent decimal numbers exactly, within its precision.
2. Comply with ANSI X3.274-1996 [1].
3. Support Python's standard operators and built-in functions on numbers.
4. Allow the user to set the precision.
5. Preserve trailing zeros, so that `Decimal("1.20")` and `Decimal("1.2")` are equal in value but remain distinguishable.

## Design decisions

### Floating point rather than fixed point

The force behind this decision is that the type must serve both calculations that need a fixed number of decimal places, such as currency, and calculations that do not, such as a rate compounded over many periods.

A fixed-point type stores a fixed number of digits after the decimal point. It suits currency directly, but a result such as the quotient of two prices needs more places than the operands. A floating-point decimal type stores a coefficient and an exponent, so it can represent both very large and very small values with the same number of significant digits.

The proposal chooses floating point and recovers fixed-point behavior through significant trailing zeros. A value read as `"1.20"` keeps two decimal places. Arithmetic on values with two places gives a result whose exponent is determined by the standard, and the program rounds to the required number of places with an explicit operation.

The cost of this decision is that a fixed-point user must round explicitly at the points where their domain requires it. The type does not enforce a scale.

### Bounded, user-settable precision

The precision is the maximum number of significant digits in the result of an operation. An unbounded type would need no precision setting, but some operations, such as dividing 1 by 3, have no finite decimal result. A bound makes every operation terminate with a defined result.

The precision is set by the user, not fixed, because different domains need different bounds. [TODO: the author should give the default precision and the reason for that default.]

### Construction

A `Decimal` can be built from a string, from an integer, or from a tuple of sign, digits and exponent.

Construction from a string is exact: `Decimal("0.1")` holds exactly one tenth. Construction from an integer is exact as well.

### Example

Computing a price with tax, rounded to cents:

```python
>>> from decimal import Decimal
>>> price = Decimal("19.99")
>>> rate = Decimal("0.0825")
>>> price * rate
Decimal("1.649175")
```

## Drawbacks

`Decimal` is a second floating-point type. Users must learn when to use it rather than `float`, and must still understand rounding, because the type rounds when a result exceeds its precision.

A program's results now depend on global or per-thread settings, such as precision and rounding, that are not visible at the point of each operation.
