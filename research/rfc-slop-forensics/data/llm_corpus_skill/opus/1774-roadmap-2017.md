# Summary

This RFC proposes the 2017 Rust roadmap, in accordance with RFC 1728. The roadmap sets out where the Rust project should be in a year's time.

This year's focus is improving Rust's productivity while keeping its emphasis on fast, reliable code. By the end of 2017:

1. Rust should have a lower learning curve.
2. Rust should have a pleasant edit-compile-debug cycle.
3. Rust should provide a solid, but basic, IDE experience.
4. Rust should provide easy access to high quality crates.
5. Rust should be well equipped for writing robust servers that handle high load.
6. Rust should have 1.0-level crates for essential tasks.
7. Rust should integrate easily into large build systems.
8. Rust's community should provide mentoring at all levels.

# Prioritization

The roadmap has eight or more goals for one year. The teams cannot give each one the same attention, and some goals compete for the same people. For example, the compiler team's time can go to compile speed, which serves the edit-compile-debug goal, or to the compiler side of IDE support, which serves the IDE goal.

# Drawbacks

A roadmap focused on productivity delays work that does not serve it. Users waiting for features outside the theme will wait longer.

A roadmap with many goals may be read as a promise to meet them all. If several goals are missed, the roadmap loses credibility as a planning tool for the following year.
