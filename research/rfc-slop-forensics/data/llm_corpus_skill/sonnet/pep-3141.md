# PEP 3141: A Type Hierarchy for Numbers

## Abstract

This PEP defines a hierarchy of Abstract Base Classes (ABCs, see PEP 3119) for number-like classes. The hierarchy is `Number :> Complex :> Real :> Rational :> Integral`, where `A :> B` means that A is a supertype of B. Scheme's numeric tower [#schemetower]_ inspired the design.

## Motivation

Numeric code written in Python tests for specific types. A function that accepts "any integer" checks `isinstance(x, int)`, and one that accepts "any real number" checks a tuple such as `(int, float)`. A third-party number type, for example a fixed-point or rational type, fails these checks even when it supports every operation the function uses. The PEP proposes ABCs so that a function can ask "is this a real number?" and a class can answer yes without inheriting from a concrete type. PEP 3119 supplies the registration mechanism that makes this possible. This PEP supplies the set of classes and the operations each one promises.

## Specification

### The hierarchy

The five classes form a chain:

```
Number :> Complex :> Real :> Rational :> Integral
```

Each class is a supertype of the one to its right. Every `Integral` is therefore a `Rational`, every `Rational` is a `Real`, and so on. A function written for `Real` accepts an `Integral` argument without change.

## Mixed-type arithmetic

When a program adds an `Integral` to a `Real`, the result has to have some type. A natural rule is that the result takes the type of the less specific operand, which here is `Real`.
