# PEP 532: A circuit breaking protocol and binary operators

## Abstract

This PEP proposes a circuit breaking protocol with two method names, `__then__` and `__else__`. The protocol gives these constructs one shared definition:

* conditional expressions: `LHS if COND else RHS`
* logical conjunction: `LHS and RHS`
* logical disjunction: `LHS or RHS`
* the None-aware operators proposed in PEP 505
* the rich comparison chaining model proposed in PEP 535

The PEP also proposes two new general-purpose short-circuiting operators, spelled with the existing keywords `if` and `else`:

* right-associative short-circuiting: `LHS if RHS`
* left-associative short-circuiting: `LHS else RHS`

The PEP builds on PEP 335, PEP 505, PEP 531 and the discussions around them. The sections below say how it relates to each.

## Context

Python evaluates `and`, `or` and conditional expressions in a way that cannot be customized. A class cannot decide whether the right-hand operand of `and` is evaluated, and it cannot change what the expression returns. The language fixes both rules in terms of the truth value of the left operand.

Several earlier proposals ran into this limit from different directions. PEP 335 asked for overloadable boolean operators. PEP 505 proposed operators that treat `None` specially. PEP 531 and PEP 535 dealt with related questions about existence checks and about chained comparisons. [TODO: confirm in one sentence each what PEP 531 and PEP 535 propose and where each stops short. This draft has only their titles' numbers and the abstract's references to them, so it makes no claim about their contents beyond what the abstract states.]

Each of these proposals needs the same underlying capability: an object must be able to say, at the moment the operator is evaluated, "continue with the right-hand side" or "stop and use me as the result." The PEP proposes to define that capability once instead of once per operator.

## Rationale

The PEP's central argument is that one protocol should replace several unrelated hooks. The abstract gives the grouping but does not say which alternatives were weighed. This section therefore records only what the abstract supports and marks the rest for the author.

**The force.** At least three proposals (PEP 335, PEP 505, PEP 531) and the rich comparison model of PEP 535 each need control over when the right-hand operand of an operator is evaluated. Without a shared mechanism, each proposal would add its own hook or its own syntax.
