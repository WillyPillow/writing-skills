# PEP 650: Specifying Installer Requirements for Python Projects

## Abstract

Python package installers do not interoperate fully. pip is the most widely used installer and a de facto standard, but Poetry and Pipenv are also popular. They offer features that suit certain workflows and do not follow pip's model.

Many installers are good for users with specific needs. The same variety makes it hard for a project to support every installer. The abstract names the specific gap: there is no standard requirements file for declaring dependencies. A project that declares dependencies in one tool's format requires that tool to install them. Otherwise a tool has to emit a requirements file, which can lose information that the installer needs and which adds an extra step.

2. An installer can install a project's dependencies without invoking another installer.

### Key tension

The proposal tries to serve users who choose tools for their different features while giving them one shared interface. A shared format can only carry features that every installer agrees on. A feature particular to one tool either needs an extension mechanism or stays outside the standard. **The force.** The abstract states the force as a lack of interoperability: "each tool must be explicitly used in order to install dependencies specified with their respective format."
