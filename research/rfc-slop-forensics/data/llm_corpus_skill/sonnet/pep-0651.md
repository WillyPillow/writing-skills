# PEP 651: Robust Stack Overflow Handling

## Abstract

This PEP proposes that Python treat machine stack overflow differently from runaway recursion. A program could then set the maximum recursion depth to fit its needs, and the interpreter would give additional safety guarantees.

If the PEP is accepted, the following program runs safely to completion:

```python
sys.setrecursionlimit(1_000_000)

def f(n):
    if n:
        f(n - 1)

f(500_000)
```

The following program raises a `StackOverflow` and does not crash the VM:

```python
sys.setrecursionlimit(1_000_000)

class X:
    def __add__(self, other):
        return self + other

X() + 1
```

## Motivation

Two different things can use up stack space. The first is Python-level recursion: a Python function calls a Python function, and the interpreter counts the depth and compares it with a limit. The second is machine stack use: C code in the interpreter, or in an extension, calls other C code, and each call takes space on the machine stack. Today one number, the recursion limit, serves as protection against both. ## Specification

### Behavior

1. The recursion limit set by `sys.setrecursionlimit` bounds the depth of Python-to-Python calls.
2. The interpreter detects imminent machine stack exhaustion separately and raises a `StackOverflow` exception in that case, in place of crashing.

In the second program, `X() + 1` calls `__add__`, which evaluates `self + other`, which calls `__add__` again, through the C implementation of the operator. Each round adds machine stack use. When the guard sees that the stack is nearly full, it raises `StackOverflow`, and the program can catch it.

## Rationale

### Why separate the two concerns

The deciding reason in the abstract is that a user should be able to tune the recursion limit to the program's needs without losing protection. A single number cannot do both jobs: a low value protects the machine stack and blocks legitimate deep recursion, and a high value allows deep recursion and leaves the machine stack exposed. This is the force behind the PEP.
