# PEP 425: Compatibility Tags for Built Distributions

## Abstract

This PEP specifies a tagging system that indicates with which versions of Python a built or binary distribution is compatible. A set of three tags indicates which Python implementation and language version, which ABI and which platform a built distribution requires. The tags are terse because they are included in filenames.

## Context

A built distribution contains files that were produced for particular conditions. Some contain compiled code that runs only on certain processors and operating systems. Some contain Python code that needs a particular language version. An installer that picks a distribution from several must decide which ones can work on the machine at hand.

Without a tag in a standard place, the installer has to open the distribution and inspect it, or try it and see. A tag in the filename lets the installer decide from the name alone. The abstract says the tags are terse "because they will be included in filenames". Filenames are the only place where a decision can be made before the file is downloaded. ## Goals and non-goals

Goals:

1. A built distribution declares the Python implementation and language version, the ABI and the platform it needs.
2. The declaration is short enough to appear in a filename.

## Specification

### The three tags

A set of three tags describes a distribution:

1. *Python tag*: the Python implementation and language version.
2. *ABI tag*: the application binary interface that compiled code in the distribution expects.
3. *Platform tag*: the platform the distribution runs on.

### Why three tags

The force is that compatibility depends on three things that vary independently. A pure-Python distribution depends on the language version only. A compiled one also depends on the binary interface and the platform. If one tag carried all three, a pure-Python distribution would need a long value, or would need to say that two of the three parts do not matter. [TODO: confirm this reasoning. ## Reversibility

The tag syntax appears in filenames that people publish and that tools parse. Once published, a filename cannot be changed without breaking those tools. This makes the grammar the most expensive decision in the PEP to reverse, and the grammar needs the most justification.
