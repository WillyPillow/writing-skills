# PEP 234: Iterators

## Abstract

This PEP proposes an iteration interface that objects can provide to control the behavior of `for` loops. An object customizes looping by supplying a method that returns an iterator. The iterator has a *get next value* operation. Each call produces the next item of the sequence and raises an exception when no items remain.

The PEP also proposes two specific iterators: one over the keys of a dictionary and one over the lines of a file. It further proposes that `dict.has_key(key)` may be spelled `key in dict`.

The second author rewrote most of this PEP to describe the implementation checked into the trunk of the Python 2.2 CVS tree. The PEP is still open for discussion. [TODO: the supplied abstract ends mid-sentence ("Some of the more esoteric ..."). State which parts are still open.]

## Context

A `for` loop today depends on the sequence protocol: the loop asks the object for item 0, then item 1, and so on until the object raises an `IndexError`. An object that is not indexable by integers cannot be looped over unless it pretends to be. A dictionary is one example. A file is another.

## Rationale

**The force.** A `for` loop can only run over objects that mimic an integer-indexed sequence. [TODO: confirm and give a concrete example.]

**Options considered.** The abstract names no alternatives. The author needs to record what else was weighed. [TODO.]

Three alternatives are suggestions for the author to evaluate, not recorded options:

* Keep the sequence protocol and add a way for a container to declare that it is not indexable.
* Use a single object with a method that returns the next item, and make `for` call that method on the container itself.
* Add a built-in function that converts any container to a list before looping.
