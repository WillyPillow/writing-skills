# PEP 520: Preserving Class Attribute Definition Order

## Abstract

A class body is ordered by its nature: the attributes defined there appear one after another. That order sometimes matters, aside from readability. If the order were available outside the class body, code could use it without extra boilerplate such as metaclasses or manual lists of attribute names. Python does not currently preserve this order. This PEP changes that by recording the order in which attributes are introduced in the class body. The order is stored in a `__definition_order__` attribute of the class, which allows introspection of the original definition order. ## Motivation

Some programs need the order in which a class author wrote the attributes. A common case is a class that describes a record, a form or a schema, where each attribute is a field and the order of fields is the order of columns or of input boxes. Today such programs have two options, both named in the abstract: write a metaclass, or list the attribute names by hand in a separate sequence. The metaclass is code the programmer must write and understand for what is a small need. The manual list repeats information that is already in the class body, and the two copies can disagree after an edit.

The abstract's argument is that "this information already exists": the interpreter reads the class body in order and then discards the order. [TODO: the author to show how the order is lost today. Example of the problem in a program:

```python
class Form:
    name = Field()
    email = Field()
    age = Field()
```

A function that renders the form wants to produce the inputs in the order `name`, `email`, `age`. Today it cannot, without help from a metaclass or a hand-written list. With the PEP it reads `Form.__definition_order__`. [TODO: confirm the exact value of `__definition_order__` for this class, including whether it is a tuple or a list.]

## Specification

When a class body is executed, the interpreter records the names of the attributes in the order they are first introduced. When the class object is created, that sequence is stored as `__definition_order__` on the class.

## Rationale

### Why the interpreter should record it

The alternative is the status quo, in which programs that need the order write a metaclass. The deciding argument in the abstract is that the information already exists and that access to it is "a reasonable expectation". This is a statement about what users should expect.
