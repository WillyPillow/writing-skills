# PEP 207: Rich Comparisons

## Abstract

This PEP proposes two new features for comparisons:

- Allow the operators `<`, `>`, `<=`, `>=`, `==` and `!=` to be overloaded separately, both in classes and in C extensions.
- Allow any of these overloaded operators to return something other than a Boolean result.

## Goals and non-goals

1. A class can define each of the six comparison operators separately. A C extension can do the same.

## Design

### Separate operators

Each of the six operators maps to its own hook. A class that defines only some of them supports only those.

The force behind this is that the relations are not always related to each other. `==` and `!=` ask whether two values are the same, and the four ordering operators ask for an order. Some types have the first without the second. [TODO: name a type from the material, or ask the author for one, so the claim is not abstract.]

- *Keep the single ordering hook.* No migration is needed, and the two consequences in the Context section remain.

## Drawbacks

1. The number of hooks a type may define grows from one to six, so there are more ways to write a type whose operators disagree with each other. A type might make `<` and `>=` inconsistent. The language cannot prevent that. [TODO: confirm and say whether documentation will address it.]
