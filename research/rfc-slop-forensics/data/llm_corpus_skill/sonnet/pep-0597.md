# PEP 597: Add optional EncodingWarning

## Abstract

This PEP adds a new warning category, `EncodingWarning`. Python emits it when the `encoding` argument to `open()` is omitted and the default, locale-specific encoding is used. The warning is disabled by default.

A new command-line option, `-X warn_default_encoding`, and a new environment variable, `PYTHONWARNDEFAULTENCODING`, enable it. A `"locale"` value for the `encoding` argument is added as well. It states explicitly that the locale encoding should be used, and it silences the warning.

### The `"locale"` value

A new value for `encoding`, the string `"locale"`, tells `open()` to use the locale encoding and does not emit the warning. The code states its intent, and the behavior stays what it was.

Without this value, a developer who really wants the locale encoding would have to find another way to silence the warning, such as querying the locale and passing the result. The force is that the default encoding is used in a great deal of existing code. A warning that is always on would flood every program that relies on the default.
