## Abstract

This PEP proposes that Python treat machine stack overflow differently from runaway recursion. Under this proposal, a program can set its maximum recursion depth to fit its needs, and the interpreter provides additional safety guarantees. The abstract gives two programs to show the intended behavior.

The first program sets the recursion limit to 1,000,000 and calls a recursive function with an argument of 500,000. The abstract says this program runs safely to completion. The second program defines a class whose `__add__` method returns `self + other`. The abstract says that `X() + 1` raises `StackOverflow` without crashing the virtual machine.

## Two kinds of overflow

The PEP separates two events. Runaway recursion is a program that calls functions without end, or beyond what it intends. Machine stack overflow is the exhaustion of the native stack that the interpreter uses to run those calls. The abstract says the two should be handled differently, but it does not say how the interpreter tells them apart.
