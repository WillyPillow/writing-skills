## Abstract

This PEP proposes including a pip bootstrap executable in the Python installation. The aim is to simplify the use of third-party modules by Python users. The PEP does not propose to include the pip implementation in the standard library. It also does not propose any package management or installation mechanism beyond those provided by PEP 427, "The Wheel Binary Package Format 1.0," and the distlib PEP. ## Rationale

The distinction between including an executable and including an implementation is the central design choice. Including the executable makes the installer available at once. Including the implementation in the standard library would tie the release of the installer to the release of the interpreter.
