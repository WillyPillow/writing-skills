## Context

The language definition for Python 2.0 and before defines exactly three namespaces that are used to resolve names: the local, global and built-in namespaces. A name that is not local to a function is looked up in the global namespace, and then in the built-in namespace. [TODO: Confirm this sentence against the full PEP text. The material states only the three namespaces.]

## Motivation

Under the existing definition, an unbound local name in a function cannot be resolved in the namespace of an enclosing function. The consequence is visible in lambdas and other nested functions. They often must use default arguments to create bindings in their own namespace, so that the values they need are available when they run.

## Proposal

This PEP describes the addition of statically nested scoping, also called lexical scoping. The addition allows the resolution of unbound local names in the namespaces of enclosing functions.

Python 2.2 receives this scoping rule. Python 2.1 receives it as a source-level option.

## Consequences

The most visible consequence is that lambdas, and other nested functions, can reference variables defined in the surrounding namespace. The default-argument workaround is then unnecessary for that purpose.

Python 2.1 issues warnings about constructs whose meaning may change when the feature is enabled. The PEP relies on these warnings to flag code that the change affects.
