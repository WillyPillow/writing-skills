## Abstract

Python package installers do not interoperate completely. The `pip` installer is the most widely used and works as a de facto standard. Other installers, such as Poetry and Pipenv, are also popular because they offer features suited to particular workflows, and those features do not follow the way `pip` works. The abundance of installers helps end users who have specific needs. The lack of interoperability makes it hard to support every installer.

The specific gap is the absence of a standard requirements file for declaring dependencies. Each tool must be used explicitly to install the dependencies written in its own format. The alternative is for a tool to write a requirements file, which can lose information for the installer and adds a step. The abstract's sentence on this point is cut off after "as well as an". ## Motivation

The motivation is the cost to each tool of supporting every format in use. The abstract states it as a chain. Each tool has its own declaration format. A tool that wants to install another tool's declarations must either be run through that tool, or receive a requirements file written from those declarations.
