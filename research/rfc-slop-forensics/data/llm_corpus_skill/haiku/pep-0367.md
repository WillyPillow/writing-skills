## Abstract

This PEP proposes syntactic sugar for the `super` type. A method call written `super.foo(1, 2)` would replace the existing form `super(Foo, self).foo(1, 2)`. The new form would construct the super object automatically. It would bind to the class in which the method was defined, and to the instance the method is acting on, or to the class object for classmethods.

The current `__builtin__.super` would be aliased as `__builtin__.__super__`, and `__builtin__.super` would be removed in Python 3.0. The PEP also proposes that assignment to `super` become a `SyntaxError`, which is similar to the behavior of `None`.

## Rationale

The new form removes the repeated class name and the explicit instance from each call. The benefit the abstract offers is that the interpreter has the information needed to build the super object, so the programmer does not have to supply it. That benefit is only a benefit if the interpreter can find the information in every case the programmer can write.
