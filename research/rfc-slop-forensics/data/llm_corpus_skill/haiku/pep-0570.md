## Abstract

This PEP proposes a new syntax, the slash `/`, for specifying positional-only parameters in Python function definitions. A positional-only parameter has no name that a caller can use from outside the function. When a function that accepts positional-only parameters is called, the positional arguments are mapped to these parameters solely by their order.

## Motivation

When designing an API, library authors try to ensure that it is used correctly and as intended. A parameter's name is part of the API. Callers can pass it by keyword, and once they do, renaming the parameter breaks their code. [TODO: give an instance of a rename that broke callers, if the author has one.
