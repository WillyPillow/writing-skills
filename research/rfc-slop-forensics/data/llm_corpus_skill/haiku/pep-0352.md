## Context

In Python 2.4 and before, any classic class could be raised as an exception. The plan for Python 2.5 was to allow new-style classes as well. This makes the problem worse, because it would mean that any class, or any instance, can be raised.

## Motivation

Because any object can be raised, no guarantee can be made about the interface of exceptions. Code that catches or handles an exception cannot count on the exception having any particular behavior.

## Proposal

This PEP proposes a new superclass that all raised objects must inherit from. Requiring that inheritance allows a standard interface for exceptions, which code can rely on. It also gives all exceptions one known hierarchy to adhere to.
